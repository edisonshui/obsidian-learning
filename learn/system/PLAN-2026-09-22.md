## The constraint that reshapes everything: Codex parity

Claude Code exposes six hook events to this vault (`SessionStart`, `UserPromptSubmit`, `MessageDisplay`, `PreToolUse`, `PostToolUse`, `Stop`, `SessionEnd` in `settings.json`). Codex exposes three, in `.codex/hooks.json`: `SessionStart`, `UserPromptSubmit`, `Stop`. There is no `PreToolUse`, so there is no per-question hook, and Codex has no `AskUserQuestion` tool to hook anyway.

The audit's G6 was designed as a `PreToolUse` warning. Under the parity requirement that design cannot stand as the only implementation, because the gate would simply not exist in Codex.

What both hosts already share is Python. `.codex/hooks/learning.py` imports `.claude/hooks/obsidian-live.py` through `importlib`, and `AGENTS.md` tells Codex to shell out to `python3 .claude/hooks/learn-status.py --open-notes`. So `learn-status.py` is already a shared generator that both hosts run.

**Parity rules for every change in this plan:**

1. A gate lives in shared Python that both hosts run. In practice that means `consistency()` in `learn-status.py`, or a new sibling module it calls.
2. An inline hook is a Claude-only enhancement layered on top. It is never the only copy of a gate.
3. Gate on the record, not on the conversation. The record is the substrate both hosts write to; the conversation is not.
4. A skill edit lands in `.claude/skills/` and `.agents/skills/` in the same commit, enforced by the drift test in Phase 2.
5. New shared module goes at `.claude/hooks/jev.py`, following the existing pattern. Moving shared Python to a host-neutral directory would be cleaner, but it touches `settings.json`, `.codex/hooks.json`, `session-start.sh`, both entrypoints, and both test files. Keep it as a separate optional item, not scope for this plan.

## Where Jev fits, and where it does not

Verified against the live docs on 2026-09-22: `pip install typesafe-sdk`, key in `TYPESAFE_API_KEY` from `console.typesafe.ai/keys`, `client.system_one(state=..., questions={...})` with independent questions batched into one request. Three primitives: Choice (one of a set, reports `confidence`), Score (position on ordered levels, reports `confidence`), Noul (probability a condition holds, **no separate confidence**, so route on distance from 0.5). Input costs $0.042 per million tokens and output is free, so a pass over all 11 session notes in this vault costs well under a cent. Latency is 70 to 500 ms.

### The dividing line

`model-jaggedness/jev-1.13` states that Jev cannot reliably count items, is not a calculator, and reads dates as text rather than ordered quantities. Every gate the audit proposed is a count, a presence test, or a date comparison. So Jev buys nothing on G1, G2, G5, or the slot tally, and would make them slower, non-deterministic, and network-dependent. Those stay entirely in code. The TypeSafe guidance says the same thing: keep known rules, calculations, and exact lookups in code.

Jev's actual territory here is the set of rules the audit **rejected as ungateable because they need semantic judgment**, plus the semantic half of the ones it kept. That is a real expansion of what this system can enforce, and it is the reason the API key is interesting rather than a toy.

**Never send to Jev:** word counts, `nodes:` matching, frontmatter presence, slot distribution, the 6-hour pause bound, "longest time since checked", file existence, the active and idle clock.

### J1 — Probe self-containment (replaces G6's regex)

The highest-stakes check in the vault. `tutor.md` states the consequence: a question the learner cannot fully see produces "a wrong answer that is evidence about the interface, not about the learner", and it gets logged as evidence about the learner anyway. That corrupts `record.md`, which everything downstream reads.

The audit specified a regex for this and flagged its own weakness in the same breath: "Needs a tuned regex: 'which of the following' must be excluded." A regex for "does this question stand on its own" is the wrong instrument.

- Primitive: Noul, one per logged check.
- State: the question text and its option labels only. Nothing else, because jaggedness #8 says unrelated context lowers accuracy.
- Instructions must be explicit about the boundary case, because jaggedness #1 says the model reads literally: the phrase "which of the following" refers to the answer options, which the learner can see, and is not a dangling reference.
- Where: `learn-status.py` over every logged check in every session note. Claude Code additionally gets the inline `PreToolUse` warning into `log.md`, as a second copy, not the only one.
- Codex gets the record-layer check. It does not get the inline one, and that is stated rather than papered over.

### J2 — Is this check actually discriminating?

G4's `key: <slot>/<count>` field catches positional patterns by counting, in code. It does nothing about the other half of `tutor.md:65`: "Options must be parallel in length and phrasing so the correct one cannot be spotted by shape."

- Primitive: Choice. Put the learner's own multiple-choice question to Jev with **only** the question and its options, and none of the lesson material. Compare Jev's answer and its `confidence` against the logged key.
- If Jev picks the correct option with high confidence having never seen the lesson, the option set leaks the answer through shape: longest option, odd one out, the only grammatical one.
- This uses Jev as an adversarial test-taker against the vault's own quiz questions, which is exactly what `tutor.md:67` says the rule is for: "a check that cannot discriminate is not a check, it is a record of nothing."
- Honest caveat: Jev may answer correctly because it knows Java or Calc III, not because the options leak. So this is a flag for review, never a verdict. Calibrate it first against the roughly 40 checks already logged across the 11 session notes, and see whether the flagged set matches the questions a human would call guessable. That calibration run should be the first thing built on the key, because it also proves the plumbing end to end against real data.

**Decision, 2026-09-22 (session 4): J2 does not ship in Phase 4. It moves to Phase 5, next to J4 and J5.**

The calibration ran for real against the 7 historical checks whose option text survives in a session note, and flagged 7 of 7 at confidence ≥ 0.7. A 100% flag rate with no non-flagged check to contrast against is a null result, not a pass. "Every option set leaks" and "Jev knows C++" predict that outcome equally well, and for a set of deliberately easy recap questions the second is the likelier reading — which is the caveat this section wrote down before the key existed. Wired in as it stands, J2 would add one warning per logged check to *Record inconsistencies* in perpetuity, and a warning that fires on everything is the same as a warning that fires on nothing.

The contrast is what makes that a decision rather than a shrug. On the same day, against the same records:

- **J1** flagged 4 of 42 logged checks. All four are true positives on inspection: two in `pointers-and-references s01` ("code above, what do the two cout lines print?" at p = 0.98, and "if the last line were `cout << *b` instead" at p = 0.96), one in `math241 s01` ("what three conditions must all hold?" — of what function, the probe does not say), one in `oop s02` (a trace question over class definitions that live only in a previous message). The pointers pair is the failure `tutor.md` describes happening in the record: that check was answered wrong, and the wrong answer was logged as evidence about the learner.
- **J3** put p = 1.00 on a genuine restatement of an existing candidate, p = 0.00 on an unrelated claim, and p = 0.48 on a near-miss that shares a topic with an existing misconception but makes a different claim — routed to `new`, which is the conservative answer `learn-end` step 5 asks for.

Both of those discriminate. J2, on this corpus, cannot be shown to.

What would settle it, for whoever picks it up in Phase 5:

1. **A within-question control, not an absolute threshold.** Ask each question twice: once with its logged options, once with the options rewritten to equal length and parallel phrasing with the content held fixed. Subject competence is then constant across the pair, and the *drop* in confidence is the leakage signal. Absolute confidence on a single run cannot separate the two causes and never will.
2. **Verbatim option text in the log.** Only 7 of roughly 42 logged checks preserve their options at all; the rest record a slot (`key: N/M`) or a prose summary. Until a check logs what the learner actually saw, J2 has almost no corpus to run on, and the 7 it does have are all one subject.

### J3 — Candidate matching for preferences and misconceptions

`learn-end` step 5 asks the tutor to make a semantic identity judgment and supplies its own tie-break: "A candidate matches an existing one when it is the same claim about the learner, not the same wording. If you are not sure they are the same claim, they are not." That judgment decides whether a preference gets promoted to *Observed*, it happens once per session, and today it is unrecorded and unauditable. All 3 lines in *Observed* and all 4 in *Candidates* turned on it.

- Primitive: Choice over the existing candidate list plus an explicit "none of these, this is new" option. The `entity_alignment` cookbook is this exact shape.
- Choice reports `confidence`, so route on it, per the `confidence-routing` pattern: high means promote, low means file as new, and the middle band goes to Edison in the closing block. That matches the file's own conservative bias instead of overriding it.
- Same shape for misconception candidates in `record.md`, which follow the same two-sighting rule.
- Where: a subcommand both hosts shell out to identically, `python3 .claude/hooks/jev.py match-candidate`. Fully Codex-compatible.

### J4 — The resume.md acceptance test

G1 counts words. `records.md` states the real test and nobody checks it: "could a fresh session with no transcript continue the lesson from these files alone?"

- Primitive: three Nouls batched in one request, composed in code, rather than one vague Noul. Does it name the next concrete action? Does it name what is shaky or unproven? Does it state where each node stands? Jaggedness #1 means "could continue" on its own is too indirect to answer well.
- This is the `composite-scoring` pattern: score the dimensions separately, let code own the policy.
- Weakest of the four, and it should come after J1 through J3.

### J5 — Analogy boundary, which the audit rejected

`tutor.md`: "Always say where the analogy breaks; an analogy without its boundary teaches a misconception." Audit X7 rejected gating it because "requires deciding what counts as an analogy; cost exceeds the violation." Deciding what counts as an analogy is a semantic judgment, which is the thing that just got cheap.

- Two Nouls per node entry, batched: does this explanation draw an analogy to something outside the subject, and does it state a limit of that analogy. Code applies the rule and flags only the yes-then-no case.
- This is "split independently useful dimensions" from the TypeSafe guidance, and it is the clearest demonstration that Jev changes which rules are gateable at all.
- Low priority, high signal about the approach.

### Considered and deferred

Pre-grading free-response answers with a Noul against a rubric written before the question is asked. It would make audit X9 gateable, since X9 was rejected on the grounds that "ordering inside one file is unprovable" and an API call made before the learner answers is a real timestamp. Deferred for two reasons: it adds network latency inside the teaching loop, where `tutor.md` wants the tutor's full attention, and it invites the tutor to defer a judgment it is supposed to make itself. Revisit only after J1 through J3 are proven.

### Engineering constraints

- `.gitignore` has no `.env` entry today. Add it **before** the key touches this repo. Check `git log -p` for the key afterwards if it was ever pasted into a tracked file.
- Both hosts set hook timeouts of 5 seconds (`settings.json`, `.codex/hooks.json`). Jev at 70 to 500 ms fits, but a network failure must never block a session start or a lesson. Fail open and stay silent, the way `session-start.sh` already treats its own subprocesses: "a blocked session start is worse than both."
- No key, no network, or no `typesafe-sdk` installed must be a clean no-op that says so once, not a traceback. Both hosts run these scripts, and a tutor cannot teach if the generator crashes.
- `learn-status.py` runs at every single session start. Do not put a network call on that path. Semantic checks go behind a `--semantic` flag, run at `/learn-end` and on demand, with results cached by content hash so an unchanged note is never re-judged. Session start stays fast, offline, and deterministic.
- Typed output guarantees the interface, not the truth of the judgment. Every Jev check reports into *Record inconsistencies* as a warning for a human to read. None of them auto-repairs anything, which is the rule `CLAUDE.md` already sets for generated views.

## Session 6 — the follow-on items

### J1 inline, built

The seam the two previous declines asked for, designed before any code: **a third list in the live-log state, merged only at render time.**

The erasure was never about appending to `log.md` from another process. It is one line in `promote_or_reconcile`: `state["baseline"] = canonical`. The baseline is replaced wholesale by the JSONL transcript as soon as the visible turn lands there, so an entry with no transcript row — which a notice can never have, because no model emitted it — is dropped at the next reconciliation, not at the next keystroke. Putting the notice in `current` fails the same way one step later.

So `state["notices"]` sits beside `baseline` and `current`, reconciliation never sees it, and `all_entries()` splices it in at render time. The splice is by **anchor key, not position**: `questions-<tool_use_id>` is built identically by the `PreToolUse` branch and by `read_transcript`, so it names the same question on both sides of promotion. That was checked against the saved runtime state before it was relied on — all 100 recorded question entries carry a real `toolu_` id and none fell back to the placeholder key. An anchor that never appears parks its notice at the end rather than dropping it.

**Two channels, because they reach different readers.**

- The notice in `log.md`, on any flag at `PROBE_FLAG_AT` (0.70). That is where the learner is already reading the question, and `tutor.md` already tells them what to do about it: say you cannot see the material rather than guess.
- A `PreToolUse` deny, only at `PROBE_BLOCK_AT` (0.90). Plain stdout from `PreToolUse` goes to the debug log and never reaches the model — verified against `code.claude.com/docs/en/hooks`, which lists `UserPromptSubmit`, `UserPromptExpansion`, `SessionStart` and `PostModelSwitch` as the only events whose stdout becomes context. `hookSpecificOutput.permissionDecision` is the documented channel that does, and the docs say plainly that Claude Code "shows Claude the reason". Only `deny` is ever emitted; an `allow` from a hook would silently override the permission rules in `settings.json`.

**This departs from audit G6, which said "trace only; never block."** Stated rather than buried: a trace is only caught if the learner happens to look at Obsidian before answering, and the evidence is corrupted either way. The deny is what makes the catch reliable, and it is bounded three ways — one withdrawal per distinct question text (a second identical ask goes through, so the tutor can overrule it and no retry loop is possible), a 3-second budget inside a 5-second hook timeout, and fail-open on a missing module, missing key, dead network, or any exception.

**Calibrated against all 55 logged probes in the vault, through the real API.** 2 would block: both in `pointers-and-references s01`, at p = 0.98 and 0.96 — the pair this plan already named, and the one where a wrong answer was logged as evidence about the learner. 2 more land in the 0.70–0.90 band and get a notice while being asked anyway. 51 are untouched, including the `which of the following` boundary case, checked live. An uncached round trip measured 385 ms.

**Parity rule 2 holds and rule 1 is unaffected.** The record-layer check in `learn-status.py --semantic` is unchanged and is still the copy both hosts run. Codex has no `PreToolUse` event and no question picker to hook, so it does not get the inline half — said here rather than papered over. With no key the inline half degrades to `dangling_reference()`, which can only ever warn: withdrawing a question the learner is waiting on is the one intervention in `jev.py` with a cost when it is wrong, and the weaker instrument does not get to make it.

### The within-item control — J2 and J4's `what_is_shaky`, both shipped

Both were deferred for the same reason, recorded twice: an absolute probability on one run cannot separate "the thing I am looking for is present" from "this question says yes to whatever I hand it". The remedy both entries named was the same — score the *drop* between an item and a controlled rewrite of it.

**The word that kept it unbuilt was "rewrite".** Nothing in `jev.py` can rewrite text: Jev returns typed judgements, not prose, and asking the tutor to write the control for its own question is asking the thing under test to grade itself. So both controls here are **subtractive and mechanical** — they delete one input and never author a replacement. That is why this could be built at all.

`paired_drop(left, right)` is the shared instrument: two calls, one varied input, read the gap. Two calls rather than one batch, because jaggedness #8 means batching would put the control's state inside the item's own judgement and destroy the thing being measured.

**J4's `what_is_shaky` — the control is the question's own polarity, with the state byte-identical.** A reader that has actually read the note answers "does it name a weak point" and "is everything presented as settled" nearly oppositely. A Noul that is just agreeing says yes to both, and the gap collapses. Measured on a minimal ablation of `pointers-and-references/resume.md`, only the weak-point clauses altered:

| | `what_is_shaky` | `all_settled` | gap | absolute verdict |
| --- | --- | --- | --- | --- |
| real note | 0.98 | 0.01 | +0.97 | no finding |
| minimal ablation | 0.41 | 0.77 | **-0.36** | no finding — *the miss* |

The five live `resume.md` files sit at +0.92 to +0.98. `SHAKY_GAP_AT` is 0.5: 0.42 clear of the nearest true pass, 0.86 clear of the nearest true flag. The dimension is asked from now on.

**J2 — the control deletes the question and keeps the options.** Jev knowing the subject requires the question, so removing it drops that run to chance; options that leak through shape leak just as well without it, because none of that was ever about the question. The confound cancels exactly. Flag is `p_blind` beating `1/n` by `LEAK_MARGIN` (0.25); the drop says how much work the question was doing.

Over the 7 historical checks with recoverable option text, this flags **3, not 7 of 7** — the contrast session 4 said J2 never had. All three are defensible on inspection, and each is one of the three patterns `tutor.md:65` names: the only well-formed C++ (blind 0.88), the only non-absolute claim among two extremes (0.76), the longest option and the only one phrased as a definition (0.67). The four it clears blind at 0.10, 0.26, 0.30 and 0.48. Two synthetic controls confirm the instrument moves: a deliberately leaky set blinds at 0.91, its parallel-phrased rewrite at 0.38 against chance 0.33.

**The corpus decision: yes, log the options — by extending the field that already exists, not adding another.**

`key: <slot>/<count>` becomes `key: <slot>/<count> — options: <opt1> / <opt2> / <opt3>`, verbatim, in slot order. `learn-status.py`'s `MC_KEY` is `\bkey:\s*(\d+)/(\d+)`, so G4 reads it unchanged; the slot already says which option was correct, so the old inline `[correct, slot N]` marker is redundant and goes. One field to remember instead of two, and `encode-lessons` rung 1 applies: a check whose options were never recorded stops being representable in a well-formed log. Landed in all ten places the field is defined — `tutor.md`, `records.md`, both templates, and both host copies of `learn-check`, `learn-end` and `learn-review` — with the drift test green.

**The honest gap:** J2 has no deterministic fallback, and cannot have one. "Could these options be picked without reading the question" has no offline form. With no key it does not run, which is why it is a `--semantic` extra and never the only thing between a leaky option set and `record.md`. It is also retrospective by construction — the check is already logged as evidence by the time this reads it — so its only output is a line for a human.
